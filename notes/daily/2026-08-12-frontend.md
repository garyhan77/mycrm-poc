# 2026-08-12 (frontend)

Built the [[../00-index|MyCRM]] landing page per the user's own spec: single page, no routed sub-pages. Header top-left, search bar + button, one big table (every `Customer` column, sortable headers, row/select-all checkboxes), pagination bottom-right, Add/Delete below. Add and Edit share one modal — there's no separate read-only view screen.

Needed two small backend additions to support it: `DELETE /api/customers` for bulk delete (checkbox selection), and a widened `sortBy` whitelist so every column shown is actually sortable.

No `chromium-cli` available locally, so verified in a real browser with a small Playwright driver script instead (see [[../research/framework-choices|framework-choices]] for the general research log — this was tooling, not a stack decision, so not logged there). Walked the full flow: sort, search, add, edit, checkbox select, bulk delete.

Caught a real bug this way, not a scripting issue: `assertEmailIsAvailable` only checked non-deleted rows, but MySQL's unique index on `email` still counts soft-deleted rows. Re-adding a customer with a previously-deleted customer's email caused a raw 500 instead of a clean 409. Fixed with `withDeleted: true` on that lookup.
